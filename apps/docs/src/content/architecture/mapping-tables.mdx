# Mapping Tables

Mapping tables preserve source-system values while resolving them into the standardized Metrics taxonomy. They are property-aware, source-application-aware, and sit between raw ingestion and production dimensions or reporting views.

This document reflects the latest Dataform definitions mirrored from `packages/dataform` to `REVREBEL/Metrics-Dataform`.

## Status summary

| Table | Warehouse status | Primary purpose |
|---|---|---|
| `metrics_core.map_segment` | Implemented | Map source segment codes to commercial and finance segments |
| `metrics_core.map_roomtype` | Implemented, legacy-compatible schema | Map source room types, room classes, beds, features, and room pools |
| `metrics_core.map_source` | Implemented | Map source and subsource codes to source, subsource, and channel |
| `metrics_core.map_rate` | Implemented | Map rate codes to rate type, company, segment, channel, source, subsource, and consortia |
| `metrics_core.map_hotel` | Planned in app registry only | Resolve source property identifiers to `dim_property` |
| `metrics_core.map_channel` | Planned in app registry only | Dedicated channel mapping; current warehouse mapping is handled through `map_source` |
| `metrics_core.map_market` | Planned in app registry only | Normalize source market codes |
| `metrics_core.map_agency` | Planned placeholder in app registry only | Map source agency/account values |
| `metrics_core.map_source_metric` | Architecture reference only | Map raw report columns to metric definitions; not present in current Dataform DDL |

The distinction matters: app registry entries are product scaffolding and should not be treated as deployed BigQuery tables until corresponding Dataform DDL exists.

# Implemented mapping tables

## `metrics_core.map_segment`

Maps source-application segment values to the standardized commercial and finance segment taxonomies.

| Column | Type | Description | Dependency |
|---|---|---|---|
| `property_code` | `STRING` | Property scope for the source value | Property reference; no explicit foreign key in current DDL |
| `source_application_code` | `STRING` | Application that supplied the source value | `lkp_source_application.code` |
| `code` | `STRING` | Source-application segment code | Source value |
| `name` | `STRING` | Source-application segment name | Source value |
| `description` | `STRING` | Source description, when supplied | — |
| `segment_code` | `STRING` | Standard commercial segment | `lkp_segment.code` |
| `finance_segment_code` | `STRING` | Standard finance segment | `lkp_finance_segment.code` |
| `gl_code` | `STRING` | General-ledger or guest-ledger code | External finance reference |
| `is_active` | `BOOL` | Active mapping flag | — |
| `insert_date` | `DATE` | Insert date | — |
| `updated_date` | `DATE` | Last update date | — |

### Downstream use

```text
raw segment value
  → map_segment
  → dim_segment
  → vw_segment
  → facts, snapshots, marts, dashboards
```

`dim_segment` carries `map_segment_code`, `segment_code`, `segment_group_code`, `finance_segment_code`, and `gl_code`. `vw_segment` joins those codes to their display names and sort order.

## `metrics_core.map_roomtype`

Maps source room-type and room-class values into standardized room-type attributes. This table currently uses the compatibility schema defined in `00_create_core_tables.sqlx`.

| Column | Type | Description | Dependency |
|---|---|---|---|
| `property_code` | `STRING` | Property scope | Property reference |
| `source_application_code` | `STRING` | Application that supplied the room value | `lkp_source_application.code` |
| `roomtype_map` | `STRING` | Source room-type value | Source value |
| `roomtype_code_map` | `STRING` | Source room-type code | Source value |
| `roomtype` | `STRING` | Standard room-type name | Inline standardized value; no current lookup table |
| `roomtype_code` | `STRING` | Standard room-type code | Inline standardized value; no current lookup table |
| `roomclass` | `STRING` | Standard room-class name | Inline standardized value |
| `roomclass_code` | `STRING` | Standard room-class code | Inline standardized value |
| `roomclass_map` | `STRING` | Source room-class value | Source value |
| `roomclass_code_map` | `STRING` | Source room-class code | Source value |
| `bedtype` | `STRING` | Standard bed type | Inline standardized value |
| `bedtype_code` | `STRING` | Standard bed-type code | Inline standardized value |
| `roomfeature` | `STRING` | Primary room feature | Inline standardized value |
| `roompool` | `STRING` | Optional standard room pool | Inline standardized value |
| `roompool_code` | `STRING` | Standard room-pool code | Inline standardized value |
| `roompool_map` | `STRING` | Source room-pool value | Source value |
| `roompool_code_map` | `STRING` | Source room-pool code | Source value |
| `related_roomtypes` | `STRING` | Descriptive list of related room types | — |
| `available_rms` | `INT64` | Room-type inventory, when known | — |
| `is_active` | `BOOL` | Active mapping flag | — |
| `insert_date` | `DATE` | Insert date | — |
| `updated_date` | `DATE` | Last update date | — |

### Known gap

The app registry currently claims a dependency on `metrics_core.lkp_roomtype`, but the latest Dataform DDL does not create that lookup. Room type, room class, bed type, feature, and pool values remain embedded in `map_roomtype`. A future normalization decision is required before the UI treats `lkp_roomtype` as available.

## `metrics_core.map_source`

Maps source-application source or subsource codes to the standard source, subsource, and channel taxonomies.

| Column | Type | Description | Dependency |
|---|---|---|---|
| `property_code` | `STRING` | Property scope | Property reference |
| `source_application_code` | `STRING` | Application that supplied the value | `lkp_source_application.code` |
| `code` | `STRING` | Source-application source or subsource code | Source value |
| `name` | `STRING` | Source-application source or subsource name | Source value |
| `description` | `STRING` | Source description, when supplied | — |
| `code_reference` | `STRING` | Declares whether the row maps a `source_code` or `subsource_code` | Controlled values: `source_code`, `subsource_code` |
| `source_code` | `STRING` | Standard source | `lkp_source.code` |
| `subsource_code` | `STRING` | Standard subsource | `lkp_subsource.code` |
| `channel_code` | `STRING` | Standard channel | `lkp_channel.code` |
| `is_active` | `BOOL` | Active mapping flag | — |
| `insert_date` | `DATE` | Insert date | — |
| `updated_date` | `DATE` | Last update date | — |

### Downstream use

`vw_source` enriches each mapping with source, subsource, channel, and channel-group names, descriptions, and sort order.

```text
map_source.channel_code
  → lkp_channel.code
  → lkp_channel.channel_group_code
  → lkp_channel_group.code
```

`vw_rate` resolves the rate mapping into display-ready attributes, including:

- rate type,
- company and industry,
- segment,
- channel and channel group,
- source and subsource,
- consortia, focus, and category.

# Standard source-application relationship

All implemented source-value mapping tables use:

```text
mapping_table.source_application_code
  → metrics_core.lkp_source_application.code
  → metrics_core.lkp_source_system_type.code
```

Do not introduce alternate mapping fields such as `source_system`, `system`, or `source_system_category` for this relationship.

`map_hotel` is the exception: property identity should resolve directly to `dim_property` and should not require source-application classification unless a future property-identifier model explicitly adds it.
