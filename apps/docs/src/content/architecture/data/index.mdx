## Source ownership

Use the following authority order when these sources differ:

1. Linear defines product intent, approved terminology, and initiative or project boundaries.
2. Repository code defines the current application implementation.
3. Dataform defines the current warehouse schema, dependencies, mappings, lookups, and assertions.
4. Documentation explains the system but must be reconciled against the sources above.
5. Registries and fixtures are application scaffolding unless current implementation confirms otherwise.

Documentation must distinguish:

```text
IMPLEMENTED
PLANNED
COMPATIBILITY
DEPRECATED
UNRESOLVED
```

## Domain documentation boundary

Domain pages explain source-specific or business-specific behavior. They do not own shared warehouse definitions.

Examples:

- RMS pages may explain IDeaS pace behavior, but the shared pace fact grain belongs in the fact-table documentation.
- GA4 pages may explain session and acquisition semantics, but the shared report and mart conventions belong in the reporting documentation.
- Segment, source, channel, rate, and room-type pages may explain business taxonomy, while physical schemas belong in the lookup, mapping, and dimension catalogs.
