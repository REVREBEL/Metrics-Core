# Mapping and Lookup Dependencies

This page documents the current semantic and execution dependencies for implemented lookup and mapping objects.

BigQuery does not enforce these relationships as physical foreign keys. Dataform, ingestion services, application validation, and data-quality checks must preserve them.

## High-level graph

```text
lkp_source_system_type
  └── lkp_source_application
        ├── map_segment
        ├── map_roomtype
        ├── map_source
        └── map_rate

lkp_segment_group
  └── lkp_segment
        ├── map_segment
        ├── dim_segment
        ├── map_rate
        └── lkp_rate

lkp_finance_segment
  ├── map_segment
  └── dim_segment

lkp_source
  ├── lkp_subsource
  ├── map_source
  ├── map_rate
  └── lkp_rate

lkp_channel_group
  └── lkp_channel
        ├── map_source
        ├── map_rate
        └── lkp_rate

lkp_consortia_focus ─┐
lkp_consortia_category ─┴── lkp_consortia
                              ├── lkp_agency
                              ├── map_rate
                              └── lkp_rate

lkp_industry
  └── lkp_company
        ├── map_rate
        └── lkp_rate

lkp_ratetype
  ├── map_rate
  └── lkp_rate
```

  → lkp_segment.segment_group_code
  → lkp_segment_group.code

  → lkp_subsource.source_code
  → lkp_source.code

map_source.channel_code
  → lkp_channel.channel_group_code
  → lkp_channel_group.code

map_rate.company_code
  → lkp_company.industry
  → lkp_industry.industry

map_rate.consortia_code
  → lkp_consortia.consortia_focus_code
  → lkp_consortia_focus.code

map_rate.consortia_code
  → lkp_consortia.consortia_category_code
  → lkp_consortia_category.code

`map_roomtype` has no current lookup dependencies for room type, class, bed, feature, or pool. Those standard values are embedded in the compatibility mapping schema.

# Dataform execution dependencies

```text
05_create_segment_tables
  → 05_migrate_segment_mapping_schema

06_create_source_channel_rate_tables
  → 06_migrate_source_rate_mapping_schema
  → 06_migrate_subsource_parent_source
```

The migrations add columns to pre-existing tables because `CREATE TABLE IF NOT EXISTS` does not update an existing schema.

##

# Required validation

At minimum, assertions or scheduled checks should detect:

- mapping rows with unknown `source_application_code`;
- mapping target codes missing from their lookups;
- invalid `segment_group_code`, `source_code`, or `channel_group_code` parents;
- invalid consortia focus/category relationships;
- `map_source.code_reference` outside `source_code` or `subsource_code`;
- active mappings with null required source values;
- contradictory or incomplete `map_rate` classifications;
- orphaned dimensions after mapping changes;
- text drift in `lkp_company.industry`;
- duplicate property/application/source-code mappings.

Current DDL descriptions express semantic relationships, but this documentation does not claim that every check above is already implemented as a Dataform assertion. REV-70 owns the implemented-versus-recommended assertion inventory.
