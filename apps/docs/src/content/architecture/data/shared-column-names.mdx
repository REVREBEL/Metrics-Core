# Shared Column Name Catalog

This page is the canonical audit reference for shared Metrics warehouse column names. Use it when reviewing source pipelines, standardized upload files, staging tables, Dataform models, and downstream reporting contracts.

This catalog records approved names and abbreviations. It does not automatically rename existing physical columns. Repository code and current Dataform definitions remain implementation truth, and any physical rename requires dependency review and migration handling.

Where this catalog conflicts with an older column-level rule in `naming-and-modeling-conventions.mdx`, this catalog governs the shared column name. The broader naming-and-modeling page continues to govern object families, grain, status, and migration discipline.

## Core rules

- Use lowercase `snake_case`.
- Use `no` as the approved abbreviation for number.
- Use `amt` as the approved abbreviation for a monetary amount.
- Do not add `_name` to standard business label columns. Use paired label and code fields such as `rate` and `rate_code`, `source` and `source_code`, or `segment` and `segment_code`.
- Preserve source-qualified prefixes such as `pms_` and `crs_` when the field intentionally represents a source-native value.
- Use governed metric abbreviations consistently.

### Governed metric abbreviations

| Abbreviation | Meaning |
|---|---|
| `rev` | Revenue. |
| `rms` | Rooms or room production. |
| `adr` | Average daily rate. |
| `occ` | Occupancy. |

## Source-system fields

These two fields are approved and have different meanings:

| Approved column | Meaning or usage |
|---|---|
| `source_system` | Specific source application or system, such as `STAYINTOUCH`, `DUETTO`, `SYNXIS`, or `SITEMINDER`. |
| `source_system_type` | Source-system category, such as `PMS`, `RMS`, `CRS`, or `BOOKING_ENGINE`. |

`source_system` identifies the specific system. `source_system_type` classifies that system. Neither field substitutes for a business-domain code such as `source_code`.

The earlier `source_application_code` guidance remains an implementation compatibility reference for existing Dataform objects. New shared source contracts use `source_system` and `source_system_type`; migrations of existing physical columns require a separate dependency review.

## Revenue and monetary columns

`amt` is the approved monetary suffix for shared Metrics column names. This supersedes the older `_amount` target examples in `naming-and-modeling-conventions.mdx` for new shared column contracts. Existing `_amount` physical columns remain compatibility fields until migrated.

| Approved column | Meaning or usage |
|---|---|
| `rev_addon` | Add-on revenue. |
| `rev_fb` | Food-and-beverage revenue. |
| `rev_other` | Other revenue. |
| `rev_total` | Total revenue. |

## Source-native PMS dimensions

| Approved column | Meaning or usage |
|---|---|
| `pms_segment` | PMS-native segment label or value. |
| `pms_source` | PMS-native source label or value. |
| `pms_sub_segment` | PMS-native sub-segment label or value. |

These source-native fields may coexist with governed Metrics fields such as `segment`, `segment_code`, `source`, `source_code`, `subsource`, and `subsource_code` when lineage and reconciliation require both representations.

## Reservation-level helper columns

| Approved column | Meaning or usage |
|---|---|
| `unique_lead_days` | Reservation-level lead days populated according to the source pipeline's deduplication convention. |
| `unique_nights` | Reservation-level nights populated according to the source pipeline's deduplication convention. |

These fields must not be summed blindly across stay-date grain. Their population and aggregation rules belong in the source documentation and metric definition.

## Standard label and code pairs

Use the business label without `_name`, paired with the controlled code:

```text
rate          + rate_code
source        + source_code
channel       + channel_code
segment       + segment_code
subsource     + subsource_code
roomtype      + roomtype_code
property      + property_code
```

Source-qualified variants follow the same intent where both a label and code are available:

```text
crs_channel       + crs_channel_code
crs_subsource     + crs_subsource_code
pms_rate          + pms_rate_code
```

## Audit use

When reviewing a standardized source file:

1. Compare every shared field against this catalog.
2. Identify source-native fields that intentionally remain outside the shared vocabulary.
3. Record compatibility exceptions rather than silently creating another synonym.
4. Verify physical implementation against current Dataform before describing a rename as implemented.
5. Update this catalog when a durable shared naming decision is approved.
